# Correspondencia comercial Sendcorex
El CRM no es un cliente de correo. La pestaña Sincronización de correo configura una conexión de lectura; la ficha de cada negocio muestra su historial persistido en PostgreSQL.
- Webmail: generar token de acceso y refresh token del buzón comercial; se permite una credencial de solo lectura.
- Developer: API key con permiso logs:read. Los registros de envío del remitente conectado incluyen API, SMTP y campañas, excluyendo warm-up; la retención documentada es 60 días (la importación inicial pide los últimos 59 días para evitar el límite).
- Configurar en Administración → CRM → Sincronización de correo. Las credenciales permanecen cifradas y no se devuelven al navegador. Si ya había buzón, añadir la clave de logs y sincronizar una vez para autorizar al trabajador.
- El trabajador existente en Docker usa la red privada y firma sus peticiones internas; la sincronización sigue aunque el navegador esté cerrado. Cada ciclo de importación pagina y guarda su cursor, tiene un lease persistente, y una vez completado se vuelve a ejecutar a partir de cinco minutos. Se releen ventanas solapadas (dos días para entrada, siete para envíos) para captar retrasos y estados. Los cuerpos previamente guardados no se vuelven a descargar. Si falla, conserva la información local y muestra el error.
- El historial usa coincidencia exacta de dirección normalizada con correo DENUE o correo público. Direcciones compartidas se muestran en todos los negocios que las tengan; no se infiere identidad por nombre. El listado consulta solo direcciones de su página. Se registra asunto, cuerpo disponible en texto, fecha, dirección y estado; no se ejecuta HTML ni se descargan imágenes o adjuntos.
- El estado comercial pasa de pendiente/revisado a contactado cuando Sendcorex confirma aceptación por el servidor del destinatario; no se alteran estados posteriores ni bajas. No equivale a lectura. Los rebotes o envíos fallidos aparecen como intentos, no entregas.
- La entrada se obtiene de INBOX; no se garantiza recuperar mensajes eliminados o archivados antes de sincronizarlos. Los envíos aparecen al obtener un estado final en los logs; no se recuperan cuerpos que el proveedor no conserve. La primera sincronización debe comprobarse con una cuenta real y correo de prueba legítimo.
- No se envía ningún correo ni se activan campañas automáticas con esta integración.
